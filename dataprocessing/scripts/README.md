# 脚本使用说明

全部脚本平放在本目录。在dataprocessing目录执行命令。脚本之间有解析函数复用，因此保留各自文件；无需逐个运行。

## 日常入口

| 任务 | 命令 | 是否联网 |
| --- | --- | --- |
| 重建当前全部交付与索引 | `bash scripts/重建数据.sh` | 否 |
| 只刷新目录、缺口、导航 | `python3 scripts/生成交付索引.py` | 否 |
| 继续采集全榜作品公开热评 | `bash scripts/一键采集红果全榜评论.sh` | 缓存缺失时联网 |
| 新批次刷新评论快照 | 上一命令追加 `--refresh` | 是 |
| 继续补简介 | `bash scripts/一键补齐红果简介.sh` | 是 |
| 导出已有Excel清单 | `node scripts/导出交付清单.mjs` | 否 |
| 数据关联校验 | `python3 scripts/检查采集结果.py` | 否 |
| 季数/版本规则检查 | `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts -p 'test_作品匹配.py'` | 否 |

Python解析依赖：`beautifulsoup4`、`Pillow`。复用已存OCR不需要识别模型；重新OCR才需要`rapidocr-onnxruntime`。Excel导出沿用本机`@oai/artifact-tool`环境。

## 单项处理脚本

| 用途 | 文件 |
| --- | --- |
| 月榜材料、OCR、人工核查登记 | `采集月榜原始材料.py`、`识别月榜草稿.py`、`裁切月榜核查.py`、`登记OCR人工核查.py`、`提交红果OCR核查.py` |
| 作品与AI证据 | `作品匹配.py`、`核实AI制作.py` |
| 简介与封面 | `采集红果简介封面.py`、`批量补齐红果简介.py`、`持续补采.py`、`红果剩余材料.py`、`整合红果交付.py` |
| 系列、出品、原著与重复 | `合并红果系列.py`、`核实红果关系.py`、`解析制作方项目.py`、`核查交付重复.py` |
| 全榜评论与下载队列 | `采集红果全榜评论.py`、`原子下载队列.py` |
| 第三方网页、书页和日榜解析 | `解析百科搜索.py`、`解析百科与扩展.py`、`解析作品证据.py`、`解析日榜与留存.py`、`解析日榜作品.py`、`解析原著页.py`、`关联原著与作者.py`、`双榜同月候选.py` |
| 历史试采，保留供方法复现 | `采集红果页面.py`、`提取出品与改编线索.py`、`提取短剧日榜.py`、`提取红果热评.py`、`批量采集红果评论.py`、`提取分层评论.py`、`提取抖音公开索引评论.py`、`红果简介封面查重.py` |

原子下载队列的`prepare`仅生成任务，`finalize`按请求日志验收；中间的curl下载需单独运行。失败队列仍保留原因，不把已删除的失败片段算作材料。

原`重建增量资料.sh`的处理与当前交付重建已合并为`重建数据.sh`；原`data/红果简介封面/下载缺失封面.sh`没有实际任务，已删除。
