# 数据说明与待办

本文件合并原来的采集计划、采集进度、作品去重说明和逐项验收清单。当前数据入口统一看[项目首页](../README.md)，报道设计仍以用户原方案为准。原方案及两份课程Word留在上级项目根目录，未作修改，也不纳入公开代码仓库。

## 当前样本

范围是2026年7—10月，5、6月停止补采，抖音暂缓。800条是“月份×平台×名次”的上榜记录，红果与抖音各400条。红果400条榜图转录已全部核查，抖音353条待核。

红果400条对应368部作品候选；341部有平台系列号，合并到169个系列，另27个待核单元。196是暂定统计单元，尚非已确认的独立故事数。不同季分别计作品，同一作品跨月上榜保留各月记录。

400条均有至少一套简介封面候选：392条原始HTML、2条网页工具快照、5条第三方材料、1条同名双版本待定。369份版本封面按图片内容去重为366张。3260条公开热评覆盖394条上榜记录，6条入口或页面待补；这不是全部历史评论。

## 统计与清洗规则

1. 用 `ranking_id` 连接上榜记录，`series_id → work_id → material_id` 连接系列、分季作品与版本材料。作品ID采用系列号—季号：明确季数为S代码，仅数字编号候选为N代码，未标季为SU，不默认第一季。平台原作品编号另存。
2. 平台系列号一致才正式合并。完整剧名、季号、形态、出品署名和首见时间共同核查版本。跨平台同名、近名和推荐卡片均不直接证明同一作品或同系列。
3. 原始署名、制作方/版权方、7月抖音关联方分列。“待认领”“待确认”和缺失不是具名出品公司。品牌/账号与企业主体、联合署名与具体分工分开。
4. 红果峰值热度与抖音播放增量不相加或换算人数。正式分析明确全榜、作品、独立系列和已确认AI样本各自分母。
5. AI证据按具体季/作品、系列报道、平台分类和第三方标注分级。3D漫不直接等于AI制作，未找到证据也不等于非AI。Hugging Face语料的AI受众标签不用于认定AI制作，脱敏编号不能冒充平台作品ID。
6. 原著官方页只能核实书目和作者，不能自动确认某季改编或授权。第三方候选、主创自述、官方声明和媒体证据分别保存；关系未知不能记为原创。
7. 简介用于宣传文案及其所描述情节分析，不等同于整部正片。相似度主分析排除同系列；精确同图、近似图、同作品重复上榜分别统计。
8. 评论为不同采集时间的公开页热评，通常每版9条，1版2条，没有实现历史翻页。181条疑似主创/推广需人工核角色，不直接当普通观众；只导出展示名哈希，不导出用户名、头像或用户ID。
9. 所有来源保留URL、快照、采集时间、SHA256。来源材料为采集时或工具快照版本，不能默认是上榜当月版本。OCR修改写入补录JSON，原图异常保留注释，不改写原图。

## 采集和重建

日常只用两个入口，全部脚本均集中在 `scripts/`，没有子目录。

```bash
# 离线重建数据、交付表、关系和索引，不联网
bash scripts/重建数据.sh

# 继续收集全部上榜作品公开热评，优先使用已校验缓存
bash scripts/一键采集红果全榜评论.sh
# 需要新批次快照时追加 --refresh
```

具体脚本与使用顺序见[脚本说明](../scripts/README.md)。Python依赖为 `beautifulsoup4`、`Pillow`；只有重新执行图像识别需要 `rapidocr-onnxruntime`，复用已存OCR无需重新安装。Excel导出沿用现有 `@oai/artifact-tool` 环境。

公开页面按队列低频请求，失败临时文件不入库，成功后校验页面作品ID/标题。可直接用curl执行下载；不把下载成功、非空或机械检查通过当作身份已确认。

## 当前红果优先顺序

1. **先核准分析底表。** 红果400条OCR已核完，接着核关键作品版本、27个系列待核单元和素材缺口，确定全榜与已确认AI作品各自的分母。
2. **开始简介与评论编码。** 先写编码规则、做小批试标和抽检，再批量处理。主创/推广与观众反馈分开。
3. **做跨系列封面与剧名分析。** 在已核实的作品集合上跑DINOv2、BGE-M3，保留高/中/低分样本抽检，系列内部相似单列。
4. **形成来源解释。** 继续补出品主体和原著改编证据，把相似度与题材、出品方、原著交叉；未确认关系保留未知。
5. **制作图表与报道。** 先完成红果主体叙事，再按后续决定处理抖音/双平台比较。人数趋势与AIGC文本检测按原采集计划作为补充项，不阻塞核心。
